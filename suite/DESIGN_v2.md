# HarnessBench 设计定案 v2

> 2026-07-29 收敛。取代此前的 40 叶 / 19 类 / LLM 判据体系。
> 触发这次重做的判断：**我们把"给交付物打分的工具（LLM 判官）"错用成了
> "测 harness 行为的仪器"**。harness 行为是机械事实，机械事实要用程序对着我们埋的真值查。

---

## 零、要回答的问题

**这个 harness 好不好？** 拆成两个数：

```
有效 run = 装置健康的 run（装置坏的作废重跑，不进分母）

缺陷率 = fail 数 / 有效 run 数                    ← 它做错了吗
致害率 = (fail 且导致交付失败) 数 / 有效 run 数     ← 错得要紧吗
```

恒有 `致害率 ≤ 缺陷率`。**两者的差 = 模型扛住的部分**（实测占 34%）。

两个数必须并排报，不合成：

- 只报致害率 → 漏掉"模型扛住了"的缺陷。而模型在变强，**同一缺陷弱模型 3/3 中招、强模型 0/3**（G8 实测），只看致害率等于让强模型替 harness 遮丑。
- 只报缺陷率 → 高估危害。日志没时间戳是真缺陷，但交付照样成。

## 一、结构：两层，不是三层

```
component（7 个）  →  rubric（带 pressure 标签）
```

**取消 leaf 层。** 理由：

- leaf 原本兼做「标记处境」和「汇总单位」两件事。新设计里 **处境已是 rubric 的显式字段**，前者被取代
- 30/40 个 leaf 只有 1 道题，统计上撑不起一层
- 维护成本真实：实测 6 个 leaf 名字互相冲突、N3 两道题挂错 leaf（`g` 打成 `d`）

`pressure` 作为**标签**保留（不是层级），用于分组与横切视图。

### 7 个 component

| | 名称 | 测什么处境 |
|---|---|---|
| **C** | Context | 材料超窗、被压缩、被截断时，任务必需的东西还在不在模型手里 |
| **E** | Exec | 命令失败/超时/挂住时，模型收到的是不是真相 |
| **G** | Governance | 该拦的拦住了吗、范围与声明一致吗、密钥漏没漏 |
| **L** | Lifecycle | 跨轮跨会话、派发、重试、预算耗尽时，状态还对不对 |
| **O** | Observability | 出了事回头查得清吗——错误从哪来、每步干了什么、花了多少 |
| **T** | Tools | 工具注册、参数、返回结构、并行、能力缺位——工具面可靠吗 |
| **V** | Verification | 模型说它成功了——真的成功了吗 |

每个 component 下 15–30 条 rubric。

### 机制视图（横切，不当行）

厂商文档的机制维度（goal / SubAgent / Context 管理 / 问人机制 / 安全沙箱…）
**不做表的行**，做**存好的横切视图**——因为一个机制的行为必然散落到多个行为面。

例：`goal 视图` = 拉取「跨轮状态保持」+「预算收场」+「假完成」+「goal×压缩」四组 rubric。

```
主表      行 = 7 component × 列 = harness    ← 打分、可比、不重不漏
机制视图  goal / SubAgent / …                ← 横切，回答「这个设计好不好」
```

同一批数据两种读法，rubric 不重复挂。

## 二、承重真值：探针埋在材料里

**不做外挂探针**——线性加探针会让题目看着不像真实场景，模型也有理由绕过。

> **承重真值**：真值必须是完成任务**必须用到**的材料内容。
> 不用它交付不了 → 模型没法绕过 → 丢了一定在交付物上暴露 → 程序可查。

四条设计规则：

| 规则 | 含义 |
|---|---|
| **承重** | 不用它就交不了差 |
| **唯一可辨** | 值本身像 ID，不像自然语言 |
| **不可推导** | 只能从那份材料读到，别处推不出 |
| **落点已知** | 我们知道它该出现在交付物的哪个字段 |

**现有 34 道 M 系列已经是这个形状**（12 批次 → 各取回执码 → 写进
`output/xxx.json`），只需补 `ground_truth` 声明使其可程序查收。

### 一个通用技巧：两侧计数取差

```
harness 的行为 = simulator 账本（真实到达）− 轨迹（模型发起）
```

差额只可能来自 harness——它代发了、重试了、或者吞了。
**两边都是机械计数，差额天然是 harness 的贡献**，无需任何判断。
适用于 L 维（静默重试、恢复重放）、O 维（用量记账）、E 维（超时后进程状态）。

## 三、分母：我们施加压力的 run 数

**不是**「机制触发的 run 数」。后者会**奖励逃避机制的 harness**：
Codex 90% 硬顶静默忽略 → 压缩不触发 → 分母为 0 → 看起来最干净。

每个 run 的判定：

```
施加压力 → 机制触发 → 真值查收到  = pass
施加压力 → 机制触发 → 真值丢了    = fail
施加压力 → 机制没触发 → 再查真值还在吗
                       ├ 在   → pass（用别的方式解决了，真本事）
                       └ 不在 → fail（换了个方式丢的）
```

**"机制触发了吗"退出判据，只作诊断信息记录。**

## 四、判定只有两态：pass / fail

取值集合就两个。此前写成「四态」是把**不同层次的东西塞进了同一个集合**——
装置健康是 run 的准入条件，绕过测量面是数据质量问题，两者都不是「判定结果」。

| 层 | 是什么 | 归属 |
|---|---|---|
| **判定** | `pass` / `fail` | 取值集合，就这两个 |
| **准入** | 装置健康吗（轨迹抓到了/真值文件在/探针装载了）| **前置门**——坏了就作废重跑，不产出任何判定 |
| **格子标注** | 「无此能力」+ 结局代价 | 事实标注，不是取值 |
| **诊断指标** | 未抵达率 | 数据质量，不是 harness 的分 |

```
run 跑完 → 装置健康吗？
           ├ 否 → 作废重跑，不进表
           └ 是 → 判定：pass / fail
```

### 模型绕过测量面 → 判 pass，另记未抵达率

模型写 `cmd; echo $?` 把退出码换成了 `echo` 的——**harness 确实没违背 rubric**
（它如实回传了被问的东西），按定义就是 `pass`，不需要造新状态。

但**单独记一个「未抵达率」**，它衡量的是**我们这批 run 的数据质量**，不是 harness 的分：

```
未抵达率高 → 这批 run 测不到东西 → 题目/材料要改，不是 harness 的问题
```

放表尾诊断区，与缺陷率/致害率分开。

### `N-A` 从取值集合里删除

它含混，四种东西全往里倒过——实测 C 组 142 条 N-A，逐条读理由，绝大多数是
「我的证据包里没装 X」，而 X 在原始数据里都存在（工具返回结果、系统提示、题面材料）。
**是我没装，不是拿不到。**

## 五、能力缺失：给代价，不给分

harness 没有某项能力时，**不是 N/A，是一个测量结果**：

| | N/A（旧） | 无此能力（新） |
|---|---|---|
| 含义 | 我们没测出来 | **测出来了：它没有** |
| 确定性 | 重跑可能变 | 确定性事实（看工具面即知）|
| 后果 | 悬空 | **挂着结局代价** |
| 是谁的问题 | 不明 | 明确是被测对象的设计选择 |

表上占一格，写「无此能力」+ 实测代价：

```
问人机制    OC 无此能力  ·  CC 全模式  ·  Codex 仅 Plan mode
            └ 代价：歧义类题 OC 3/12 · CC 9/12 · Codex 5/12
```

汇总时该 rubric **分子分母都不进**（强行算 0% 或 100% 都是伪精确），但**必须占位显示**。

### 缺能力不是免死金牌

| | 判什么 |
|---|---|
| 没有 + **从没宣称** | 中性设计选择，不算缺陷，只挂结局代价 |
| 没有 + **宣称了** | **缺陷**（误导模型），照判 fail |

依据是我们早定的案：**系统提示是 harness 的一部分**，说了能做却做不到就是它的错。

### 防"极简 harness 满表无此能力"

结局层是共享的、不分维度的——所有 harness 用同一批题、同一批模型、客观判分。
**机制维度回答"它哪里做得对/错"，结局层回答"它到底行不行"。**
缺能力可以在前者合法地"无此能力"，躲不开后者。

## 六、汇总与呈现

| 项 | 定案 |
|---|---|
| 汇总方式 | **rubric macro-average**（每条等权），不按题数加权——加题不改分 |
| 一级格子 | 缺陷率 / 致害率 / 最严重 rubric / 已测比例 |
| 证据等级 | **L2 已复现**（≥3 run 一致）· L1 单题线索 · L0 UNTESTED，**只有 L2 进汇总** |
| 数据来源 | 每条 rubric 标 `source: program \| llm`，表上也标。混着用可以，混着信不行 |
| 多模型 | 5–6 个模型，报**中位数 + 极差**（不报平均）；极差 >40pp 自动标"模型敏感" |
| 跨家范围 | **可移植栏**（处境 rubric + unified_h）三家都填；**家内栏**（旋钮级）只填 OC，不参与跨家比 |

## 七、判据由谁执行

| component | 主要来源 | 理由 |
|---|---|---|
| C / E / G / O | **program** | 处境可注入、真值可查收，翻转率 0 |
| T | 大部分 program | 注册合规/参数上限/畸形/并行都是机械事实 |
| L | 混合 | 幂等/回滚/重放可程序查（两侧计数取差）；goal 裁决要判 |
| **V** | **llm** | "声称成功 vs 实际"要读语义 |
| T 里的「缺位可读性」 | **llm** | "模型能不能读出这个能力没有"要读语义 |

LLM 格必须带守卫：`votes: 3`（多数决）+ `quote_required` + `quote_verified`（程序回查）。

**回查的能力边界写死在文档里**：它证明"这段话在证据里"，
**不证明"这段话支持这个结论"**——后者只能人看。
且 **回查失败 ≠ 结论是假的**，只意味着未验证。两者处置不同：假的要删，未验证的要补证据。

## 八、归因分类

在原七分类基础上新增一类：

| 归因 | 含义 |
|---|---|
| `harness_caused` | harness 缺陷污染了轨迹信号（**最有价值**：这条轨迹会假罚一个做对了的模型）|
| `harness_defect_absorbed` | 缺陷真实，但模型扛住了 |
| `unrelated_defects` | 两边各有问题，无因果 |
| `agent_caused` | harness 正常，交付物错 |
| `clean` | 都正常 |
| `inconclusive_device` | 装置坏了，作废重跑 |
| `inconclusive_unmeasured` | 有层没测到 |
| **★`documented design limitation`** | **文档明文承认的设计取舍**——不是 bug，但误导面仍成立（如 deny 不查副作用）|

**因果链在新设计里是程序走的**，不再由判官串：

```
真值曾在上下文  ∧  交付物错  ∧  中间发生了压缩
       ↓              ↓             ↓
  工具返回原文    交付物字段    压缩计数/compact entry
       ↓
  harness_caused（三个都是机械事实）
```

## 九、装置层的四条铁律（都是踩出来的）

| # | 铁律 | 踩出来的实例 |
|---|---|---|
| ① | **装置故障必须显式标记，不许静默降级成 N-A** | 判官余额耗尽污染 62/74 题，数据看起来完全正常；后来补丁吃掉一行常量，因为有这条规矩才显示成"装置故障 4 题"而不是 4 条 N-A |
| ② | **证据切片必须能装下判据要的东西** | 145/563（26%）判据掉兜底切片（无 result 字段），判官照着缺口给出言之凿凿的 fail |
| ③ | **证据包做的任何删减必须逐条标出** | 判官判"参数被截断且无标记 → harness 缺陷"，那 3 处截断**是我砍的** |
| ④ | **承诺了的核验必须真的跑** | 提示里写"我们会回查引文"，链路里根本没调；实测 7–11% 的 fail 引文站不住 |

> **一条通用的：凡是靠字符串判断"某个东西存不存在"的检测，
> 都要先问一句——我匹配到的，会不会是我自己写的那行字？**
> 这一天里同类错犯了三次。

## 十、为什么放弃"打磨 LLM 判官"这条路

四组受控实验（各 2 轮、同数据、温度 0）：

| | A 基线 | B 改判据+温度0 | C 套判据目录 | D 修装置 |
|---|---|---|---|---|
| 判据级一致率 | 85.9% | 86.6% | 85.8% | 84.5% |

**四次干预，总一致率纹丝不动。** 563 条 LLM 判据 × ~14% 翻转 ≈ 每次重跑 80 条判决换值，
而真缺陷信号总共只有 ~50 条 fail（其中约 20% 还是我们自己的装置伪影）。
**噪声 ≥ 信号，这台仪器读不出被测对象。**

D 组的对照组更致命：三条**手工核实为真**的缺陷，换了证据就翻掉两条。
**让 LLM 对着环境轨迹下判断，连真缺陷都保不住。**

反证：全库最稳那条（56 道题上翻转率 5%）恰恰是唯一一条"比两个计数"的程序形判据。
