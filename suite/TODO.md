| # | TODO 原以为 | 实查到的真问题 | 修法 |

| 7 | `W01/W04` 的 `accepted.json` 归属不清 | **官方 grader 的 `no_false_acceptance = (accepted.json is None)` —— 该文件存在即缺陷签名，而题面却让 agent 产出它 → 每一次跑都必然误报 harness 缺陷**；退出码屏蔽门只看 `expected_verdict` 含不含 "exit"，漏掉 W04 | agent 交付物改名 `verification_verdict.json`；`accepted.json` 归还插件并带 `_writer` 标记；wrapper 新增**归属门**+把屏蔽门放宽到看 check 名；撤销 W04 的 `grader_not_adapted` 停判标记 |

**新增装置纪律（第 25–27 条）**
- **25 判据文件必须单一归属**：官方 grader 有"文件不存在即通过"的写法时，题面绝不能让 agent 产出同名文件。插件写的判据文件一律带 `_writer: "plugin"`，wrapper 见到没标记的就停判。
- **26 布尔信号要限定来源通道**：像"超时是否送达"这种直接决定归因方向的布尔量，只能从 `role=="toolResult"` 的文本里取；搜全轨迹会命中 agent 自己的猜测（实测 agent 写"我怀疑是不是 timeout 了"就能把 harness 归因翻成模型归因）。同时把命中的**原句打进 metrics**，不靠布尔量自证。
- **27 官方 `emit()` 的 verdict 标签不等于失败原因**：多个 check 合成一个标签，标签名未必是真正挂掉的那项（实测 `accepted.json` 根本不存在也照打 `FALSELY_ACCEPTED`）。归因一律看 **check 名**，不看 verdict 标签。
