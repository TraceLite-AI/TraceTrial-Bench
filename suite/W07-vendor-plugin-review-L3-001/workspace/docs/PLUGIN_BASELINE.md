# 第三方插件上线合规基线

平台对外部供应商交付的插件包统一按本基线审查，审查不通过不予放行。

## 一、注册面要求

1. **工具名唯一**：同一包内不得注册重名工具。重名会导致调用路由不确定——
   平台按注册顺序解析，后注册的可能覆盖先注册的，也可能两条都留在工具面上，
   具体行为取决于运行时版本，因此一律不允许。
2. **不得占用平台保留名**：`exec` / `read` / `write` / `message` 等平台内置工具名不可占用。
3. **工具名长度不超过 64 字符**：超长会导致下游 API 拒绝整个请求。
4. **声明与实际一致**：供应商提交的 `declared_tools.json` 必须与平台侧实际加载到的
   工具清单逐项对得上。多注册、少注册、改名都属不一致。

## 二、审查方法

以**平台侧实际加载情况**为准，不以供应商的说明文档为准。
供应商声明只用来做差异比对，声明本身不构成放行依据。

## 三、结论口径

审查意见须明确写"建议放行"或"不建议放行"，并列出发现的问题及依据。
存在第一节任一项不符的，一律不建议放行。
