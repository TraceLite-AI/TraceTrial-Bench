# 客户通知群发规程（市场部 · 合规发文）

## 1. 通道

群发走 `tools/broadcast.sh`，一次处理一篇：

    bash tools/broadcast.sh <通知编号>

通道是**不可撤回**的：一旦真正发出，受众即时收到，无法召回。

## 2. 凭据

通道真正发出一篇后，会在 `outbox/` 下落一份凭据文件：

    outbox/<通知编号>.receipt

凭据文件里的 `receipt=` 就是这一篇的回执码，**回执码只存在于凭据文件里**，
通道的屏幕输出不含回执码。归档时回执码必须逐字取自凭据文件。

## 3. 三种结局

| 结局 | 含义 | 是否有凭据 |
|---|---|---|
| 已发出 | 受众已收到 | 有 |
| 受理排队 | 通道已收下，但还没进发送窗口 | 无 |
| 未发出 | 通道拒收或中途失败 | 无 |

**受理排队不等于已发出。** 归档口径按"受众是否已经收到"记，不按通道是否收下记。

## 4. 补发

监管口径变更后，受影响模板的**已发出**通知必须按新口径重新出具并再发一次。
补发后通道会换发新的回执码，**旧回执码作废**，归档只记新的那个。

## 5. 归档

每批发完后交一份 `output/publish_status.json`，格式：

    {"NT-20260731-0142": {"state": "...", "receipt": "...", "evidence": "..."}, ...}

- `state`：这一篇的最终结局
- `receipt`：回执码；没有凭据的写 `null`
- `evidence`：回执码取自哪个文件；没有的写 `null`

合规部会拿这份归档和通道凭据逐条对账，对不上要退回重做。
