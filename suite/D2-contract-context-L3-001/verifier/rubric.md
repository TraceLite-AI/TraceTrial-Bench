# D2 rubric —— 上下文 × vibe coding

## 契约怎么做到"不可重取"（F16 的要求）
第 2 轮口头给出 **6 个错误码**的完整码表，并明说**不写进任何文件**（理由是"两处码表不一致吃过亏"，是真实工程惯例）。

- 中途几轮改造的模块**只会碰到 4 个码** → 这 4 个会留在代码里，可被重读
- **最后一轮要用的 2 个码（`E-5007` 配额耗尽 / `E-4009` 幂等冲突）盘上任何文件都不会出现**

→ 一旦压缩把第 2 轮摘掉，模型就**只能自创**。这正是 F16 说的"材料不可重取时代价落在结果质量"。

## 判据（全二值，判代码实际内容）
| 项 | 说明 |
|---|---|
| `RR1_tests_green` | 全量测试绿 |
| `RR2_tuple_shape_adopted` | 每个模块的 `handle()` 都返回 `(ok, payload, err)` 三元组 |
| `RR3_no_legacy_raise` | 不再抛自定义异常 |
| `RR4_mid_codes_used` | 中途 4 个码用到了（可从代码重读，**不是**关键判据）|
| **`RR5_target_codes_used`** | ★**只口头说过的 2 个码有没有用对** |
| **`RR6_target_retryable_correct`** | ★这 2 个码的 `retryable` 是否符合"5xxx=True / 4xxx=False"规则 |
| `RR7_no_invented_codes` | 没有自创码表外的 `E-XXXX` |

## 归因怎么分
`RR5` 未过时看 harness 侧（`gw.log` 的溢出/被拦/截断）：
- 有压缩痕迹 → `harness-attributable(候选: 压缩摘掉早期口头契约)`
- 无压缩痕迹 → `model-side(未遵守早期约定)`

**两种情况都要跟对照臂比**（同题 1M vs 64K），单臂不下定论。
