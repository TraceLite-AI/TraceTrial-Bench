# 判据目录（Criterion Catalog）

> **一句话**：判据可枚举，题目专属的是**参数**不是判据。
> 目录里每条判据的措辞固定、取值方向写死；一道题只做两件事——**挑几条**、**填参数**。

---

## 结构：通用层 + 机制层

判据分两层，**两层的挑选规则完全不同**：

```
通用层（4 类）  E 执行与工具结果 · L 生命周期 · S 状态与可观测 · W 被迫返工
              ← 与叶子无关，**任何题都要查**

机制层（15 类） C T R F I G N X P D V Y Q O J
              ← **归属于叶子**：一个叶子对应 1–2 个机制类
```

### 这个结构是实测出来的，不是设计出来的

我一度认为「机制族与叶子是正交的」，理由是每个叶子平均用到 6 个机制类。
**那个结论是错的** —— 因为我给全部 74 道题都挂了 `E/L/S/W` 四个通用类，
机械地把每叶的类数抬到 ≥3。剥掉通用层之后：

| | 每叶用到的机制类 |
|---|---|
| 含通用层（错误算法）| 最少 3，中位 6，**没有一个叶子只用 1 类** |
| **去掉通用层（正确算法）** | 最少 0，**中位 2**，**17/40 只用 1 类，33/40 用 ≤2 类** |

**八成的叶子只对应 1–2 个机制类 —— 这是归属关系，不是正交。**

## 为什么要有这个目录


现状（2026-07-29 实测）：

| | HR | AR |
|---|---|---|
| 判据种类 | **213** | 282 |
| 判据实例 | 567 | 501 |
| 只用在 1 道题上的种类 | 158（74%）| 228（81%）|

**213 种里绝大多数是同义重复**——"材料存活"我写了 20 个名字、"结果完整性"写了 19 个。
归族之后只剩 **约 25 族**，而且重复度极高：**2 种判据覆盖 75 条实例**（会话完整族）。

这不只是冗余，它直接造成三个问题：

1. **不稳定。** 三轮同数据同判据实测：判据级一致率 79.5%，**`fail` 可重复率仅 48%**。
   翻转集中在少数判据上（27%–100%），而**跨题共用的最稳**——
   `hr_status_consistent` 用在 56 道题上，翻转率只有 **5%**。
   一题一写的判据没被打磨过，写死程度不够。
2. **不可比。** 每道题判据都不同 → 说不出"OC 在压缩轴上的缺陷率是多少"。
3. **维护成本。** 改一处要扫全库 213 种。收敛后只维护约 25 族 × 2–4 条。

## 三态判定顺序：为什么它是一条独立规则

目录里 52 条判据补过一条「判定顺序」，起因是实测撞到的一个逻辑洞：

```
① 机制触发了吗？  没触发 → 直接 pass（记设计分），到此为止
② 触发了，证据够吗？  不够 → N-A
③ 证据够，按 fail 条件比对
```

**顺序不能颠倒。** 颠倒之后 `pass` 和 `N-A` 的条件会同时成立——
「材料还在」为真，「拿不到压缩前后的对照」也为真（因为压根没压缩，
本来就没有前后可对照），判官两边都能选。

题库里这个洞是**写死在 rubric 里**的，而且写了两个相反的方向：

| 判据 | 它对「本轮没发生压缩」的指令 |
|---|---|
| `hr_early_material_survived` | 判 **N-A**：无压缩事件 |
| `hr_long_material_survives` | 没发生压缩时判 **pass**（设计分）|

同样的情况，两条相反的指令。这是 `pass ↔ N-A` 翻转的机械原因。
全库共 17 条写着「机制没触发 → N-A」，已统一为 → `pass`。

**判据是给判官的规格。规格自相矛盾，判官的取值就一定不稳定——
这不是模型的问题。**


## 目录的写法（照最稳那条的模式）

翻转率 5% 的 `hr_status_consistent` 有三个特征，目录里每条都必须具备：

1. **取值方向写死** —— 「若你的依据是 X，取值必须是 fail」，不留权衡余地
2. **判定对象点名** —— 说清是哪份材料/哪个字段，指不出来就判 N-A
3. **三态条件穷举** —— pass / fail / N-A 各自的确切条件都写出来

另有两条通用约定：

- **机制未触发 → pass（记设计分）**，不是 fail 也不是 N-A
- **N-A 只用于「证据不可得」**，永不当扣分

## 一、上下文与材料

### C-1a 题面材料存活
```
判定对象：{关键材料} —— 由**题面**点名的规格/清单/基线/口径文档。
          ★不是随便一条消息；指不出来就判 N-A。
fail：削减/压缩/驱逐之后，{关键材料} 在模型可见上下文里不再可引，
      表现为模型重新读取同一份文件、或后续结论与该材料不符。必须指名是哪一份。
pass：{关键材料} 仍可引；或本轮根本没发生削减（机制未触发，记设计分）。
N-A：拿不到削减前后的上下文对照。
★判 fail 必须逐字引出证据原文。
★判定顺序（先后不能颠倒）：先问「机制触发了吗」。**没触发 → 直接 pass**，不再往下看证据够不够；
  只有触发了才继续，此时证据不足才判 N-A。★「机制没触发所以没有对照可看」**不是** N-A。
```

### C-1b 多轮指令存活
```
判定对象：第 {N} 轮及更早的**用户指令**中给出的关键参数或约束。
fail：这些参数/约束在后续轮次里不再可引，模型据此产出了与之不符的结果，
      且未收到任何提示。
pass：跨轮指令仍可引；或本轮无压缩/驱逐（机制未触发，记设计分）。
N-A：拿不到各轮指令与模型可见上下文的对照。
★判 fail 必须指名是哪一条指令、哪一轮给出的，并逐字引出。
★判定顺序（先后不能颠倒）：先问「机制触发了吗」。**没触发 → 直接 pass**，不再往下看证据够不够；
  只有触发了才继续，此时证据不足才判 N-A。★「机制没触发所以没有对照可看」**不是** N-A。
```

★判 fail 必须逐字引出证据原文。

## 判据质量自检清单

每条判据必须具备三要素，缺一不可（2026-07-29 实测：初版 66 条里 **61 条不合格**，
最常见是「判 fail 未要求引原文」54 条、「未点名判定对象」52 条）：

1. **判定对象点名** —— 说清是哪份材料/哪个字段/哪次调用；指不出来就判 N-A
2. **三态条件穷举** —— pass / fail / N-A 各自的确切条件都写出来
3. **判 fail 必须能逐字引出证据原文** —— 引不出就不判 fail

外加一条**有条件**的要求：

4. **机制未触发 → pass（记设计分）**
   ★**不是每条都适用**。`S-1 状态一致`、`S-5 记录可还原时序` 这类判据，
   任何一轮都有对应记录可查，**不存在「本轮没触发」的情形**，强行加反而是错的。
   判断标准：**这条判据问的事，有没有可能在某一轮里根本不发生？**
   会 → 必须写；不会 → 不写。

### 自检脚本

```bash
python3 - <<'EOF'
import re; from pathlib import Path
t = Path("CRITERION_CATALOG.md").read_text()
for cid, name, body in re.findall(r"### ([A-Z]-\d) ([^\n]+)\n```\n(.*?)\n```", t, re.S):
    p = [k for k, pat in (("fail", r"^fail"), ("pass", r"^pass"), ("N-A", r"^N-A"))
         if not re.search(pat, body, re.M)]
    if "判定对象" not in body and "{" not in body: p.append("未点名判定对象")
    if "引" not in body and "原文" not in body: p.append("未要求引原文")
    if p: print(cid, name, p)
EOF
```
